# 回归测试（node:test + jsdom）

这套测试是 star-points 的**回归安全网**：任何改动后跑一遍，能立刻知道有没有把既有功能改坏
（这几天多次出现"改打卡坏宠物、改宠物坏总分"的情况，就是因为没有统一的回归入口）。

## 运行

```bash
cd star-points
npm install     # 首次需要（仅装 jsdom 一个开发依赖）
npm test        # 全量回归
```

## 文件与覆盖范围

| 文件 | 覆盖 |
|---|---|
| `t01_ledger.test.mjs` | 总分口径（恒等于流水加总、跳过墓碑）、`sd` 保存清理、`render` 自愈、账本合并（并集+墓碑+重算）、`syncPull` 一律合并不覆盖本地、GitHub 新建文件不带空 sha |
| `t02_checkin.test.mjs` | 必打卡 24 点扣分规则（当天不扣/次日补扫）、孩子端只写标记、家长端补记流水（自愈）、幂等、墓碑豁免、补卡半分与幂等、必打卡档 +10 / 全勤档 +20、系统流水不可删除 |
| `t03_report.test.mjs` | 报告加分构成（补卡与打卡奖励合并为一项）、答题奖励单独成项、区间过滤（本月/本年/自定义）、明细弹窗含补卡 |
| `t04_pet.test.mjs` | 宠物合并策略（陪伴起始取最早、累计取大、当日状态按较新侧、摆放可逆、已拥有并集）、喂食残留纠正、同步创建（空 sha）、409 自动重试合并 |
| `t05_login_focus.test.mjs` | 新设备登录找回账本（入口/提示引导/配令牌后自动重查）、专注页四项优化（准确优先与对比、今日推荐、成绩分析与趋势、休息提醒滚动计时） |

## 新增测试的约定

1. 业务逻辑优先写成**纯函数**（可单测），DOM 只做薄封装；
2. 断言写"行为"不写"实现细节"，避免重构即失败；
3. jsdom 里跨 realm 的对象不能直接 `deepEqual`（原型不同），用 `JSON.stringify` 或键数量比较；
4. 时间敏感的用例要显式构造时间（如 `new Date(ds + 'T23:50:00')`），不要依赖运行时刻。
